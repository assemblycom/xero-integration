## Project Overview

Next.js 16 TypeScript app that syncs invoices, contacts, items, and payments between Copilot (internal platform) and Xero (accounting software). Deployed on Vercel with PostgreSQL (Supabase) and Drizzle ORM.

**Stack**: Next.js 16, React 19, TypeScript 5, Drizzle ORM, PostgreSQL, Zod 4, Biome, Tailwind CSS 4

## Commands

```bash
pnpm dev                     # Dev server (turbopack)
pnpm build                   # Production build
pnpm build:all               # Full pipeline: env validation + migrations + build
pnpm typecheck               # TypeScript check (tsc --noEmit)
pnpm lint                    # Biome check
pnpm format                  # Biome format --write
pnpm drizzle-kit migrate     # Apply DB migrations
pnpm drizzle-kit generate    # Generate migration from schema changes
pnpm drizzle-kit studio      # Open Drizzle Studio
pnpm ex [file.ts]            # Execute TS file with tsx (includes env vars + path aliases)
pnpm test                    # Run integration tests (vitest)
pnpm test:watch              # Run tests in watch mode
pnpm test:coverage           # Run tests with coverage
```

Tests use Vitest with a real PostgreSQL container via `@testcontainers/postgresql`. Integration tests live in `test/integration/`, organized by feature and webhook event.

## Architecture

### Feature-Based Structure (Vertical Slices)

Each feature in `src/features/` follows a consistent pattern:
- `lib/` — Services (business logic, DB ops, external API calls)
- `components/` — React components
- `hooks/` — Custom React hooks
- `context/` — React Context providers
- `actions/` — Next.js Server Actions
- `api/` — Controllers for API route handlers
- `types.ts` — Zod schemas and TypeScript types

Features: `auth`, `invoice-sync`, `items-sync`, `settings`, `sync-logs`, `failed-syncs`, `webhook`

### Service Layer

Services extend `BaseService` (`src/lib/copilot/services/base.service.ts`) which provides:
- `this.copilot` — CopilotAPI client (initialized from user token)
- `this.db` — Drizzle ORM instance
- `setTx(tx)` / `unsetTx()` — Transaction support

Services that call Xero API extend `AuthenticatedXeroService` (`src/lib/xero/AuthenticatedXero.service.ts`), which ensures valid OAuth tokens before API calls.

**Flow**: API Route → Controller → Service → DB/External API

### Core Sync Flow (Webhook-Driven)

1. Copilot sends webhook to `/api/webhook`
2. Authenticate user, authorize Xero connection, validate settings
3. Service syncs entity to Xero (contacts, invoices, payments)
4. Log result to `sync_logs`; on failure, store in `failed_syncs` for retry
5. Cron job at `/app/cron/retry-failed-syncs/` retries failed syncs

### Path Aliases (tsconfig.json)

- `@/*` → `src/*`
- `@@home/*` → `src/app/(home)/*`
- `@auth/*`, `@invoice-sync/*`, `@items-sync/*`, `@settings/*`, `@sync-logs/*`, `@webhook/*`, `@failed-syncs/*` → respective `src/features/` dirs

### Database

- Drizzle ORM with PostgreSQL (singleton in `src/db/index.ts`)
- Schemas in `src/db/schema/` — tables: `xero_connections`, `settings`, `synced_contacts`, `synced_invoices`, `synced_items`
- Migrations in `src/db/migrations/` (auto-generated by drizzle-kit)
- All external data validated with Zod schemas

### Error Handling

- `BaseServerError` / `APIError` classes in `src/errors/`
- API routes wrapped with `withErrorHandler` (`src/utils/withErrorHandler.ts`)
- Sentry integration for monitoring (`src/instrumentation.ts`)

### Shared Libraries

- `src/lib/copilot/` — Copilot API client, User model, rate limiting (bottleneck), retry logic
- `src/lib/xero/` — Xero API wrapper, OAuth flow, types/constants
- `src/lib/supabase/` — Supabase client (also used for Realtime subscriptions in UI)
- `src/lib/logger.ts` — Custom logger

## Code Style

- **Biome** for linting and formatting (not ESLint/Prettier)
- No semicolons, single quotes, 2-space indent, 100 char line width
- `noExplicitAny: error`, `noUnusedVariables: error`, `noUnusedImports: error`, `noFloatingPromises: error`
- Sorted Tailwind classes enforced via `useSortedClasses`
- Import `'server-only'` at the top of server-side service files
- Do not write longer comments and always use simple words to explain the code
- Avoid use of `let` (unless it's pre-existing) and always try to use `const` instead
- Follow `DRY`, `YAGNI`, `KISS`, `SOLID` principles
